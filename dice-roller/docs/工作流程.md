# DiceRoller 工作流程

本文说明如何把 `d:\GitHub\diceRoller` 的 GDScript 工程，分阶段移植到本 C# 工程，以及日后如何抽到其他 Godot C# 项目。架构与领域定义见 [项目文档.md](./项目文档.md)。

对照原则：**先对照原版跑通一个垂直切片，再扩功能。** 不要一次性翻译全部 35 个脚本。

---

## 1. 环境

| 工具 | 要求 |
|------|------|
| Godot | **4.7**，带 .NET（与 `project.godot` 的 `config/features` 一致） |
| SDK | .NET 8（Android 导出才需要 net9） |
| 对照用编辑器 | Godot **3.x**（打开源工程 `d:\GitHub\diceRoller\godot`） |
| IDE | Cursor / VS / Rider 均可；本仓库已用 `Directory.Build.props` 把 `obj/` 放在 csproj 旁，避免语言服务报找不到 `Godot` 命名空间 |

### 1.1 日常打开方式

1. 用 Godot 4.7 打开本目录（含 `project.godot` 的 `dice-roller`）。
2. 需要对照手感时，另开 Godot 3 打开 `d:\GitHub\diceRoller\godot`。源工程 Autoload 引用了缺失的 `debug_draw`，首次打开可能报错：可暂时从 `project.godot` 去掉 `DebugDraw` 这一行再运行（不要把该修改提交回源仓库，除非你维护的就是那份克隆）。
3. 在 Godot 中用 **构建** 编译 C#；不要只靠 `dotnet build` 却从未在编辑器里导入资源。

### 1.2 源与目标的关系

```
d:\GitHub\diceRoller\godot\     只读对照；不要在移植过程中改它来“顺便重构”
D:\GitHub\Godot-DiceRoller\     本 git 仓库根
  └── dice-roller\              Godot 4 C# 工程（工作区）
```

资源从源目录 **复制** 进来，脚本 **重写** 为 C#。不要在目标工程里 `symlink` 整个 Godot 3 项目。

## 2. 移植原则

1. **场景结构可抄，节点类型要升级。** `main.tscn` 的父子关系、Timer、Area 用途保留；`Spatial`→`Node3D` 等按第 4 节改。
2. **数据与节点分离。** 面映射、统计、设置键放进普通 C# 类，Godot 节点只负责生命周期和场景。
3. **禁止新的 `$"/root/main"`。** 用 `[Export]` 节点引用、组、或构造注入。这是“能迁到其他项目”的硬条件。
4. **一次一个可玩切片。** 每阶段结束必须能在编辑器里点 Play 验证（见各阶段检查表）。
5. **行为分歧要写下来。** 物理引擎从 Bullet 换成 Jolt 后，弹跳和稳定时间不会逐帧相同。对齐的是规则（哪面朝上、何时无效、热键），不是轨迹录像。
6. **GPL。** 拷贝原资源即继承 GPL-3.0。迁入闭源游戏前先看项目文档第 3.1 节。

## 3. 推荐目录演进

当前：`scripts/Example.cs`、`scenes/example.tscn`。

移植过程中逐步变成：

```
dice-roller/
├── docs/
├── scenes/
│   ├── main.tscn                 演示应用（对标原 main.tscn）
│   └── test_headless_table.tscn  无 UI，只验证生成与点数（复用门槛）
├── scripts/                      仅 App 入口，最终可删 Example
└── addons/dice_roller/           尽量早创建，避免以后大搬家
    ├── plugin.cfg                可选；至少保证文件夹可复制
    ├── Core/
    ├── Physics/
    ├── Settings/
    ├── Ui/
```

## 4. Godot 3 / GDScript → Godot 4 / C# 对照

改脚本时按表替换，不要混用旧 API。

### 4.1 节点与资源

| Godot 3 | Godot 4 |
|---------|---------|
| `Spatial` | `Node3D` |
| `RigidBody` | `RigidBody3D` |
| `StaticBody` | `StaticBody3D` |
| `Area` | `Area3D` |
| `RayCast` | `RayCast3D` |
| `Camera` | `Camera3D` |
| `MeshInstance` | `MeshInstance3D` |
| `CollisionShape` | `CollisionShape3D` |
| `Viewport`（3D 预览） | `SubViewport` |
| `SpatialMaterial` | `StandardMaterial3D` |
| `StreamTexture` | `Texture2D` |
| `BoxShape.extents` | `BoxShape3D.Size`（全尺寸，不是半尺寸） |
| `translation` | `Position` |
| `Rect2` 控件 `rect_position` / `rect_size` | `Position` / `Size` |
| `pause_mode` | `ProcessMode` |
| `Tween` 节点 | `CreateTween()` |
| `File.new()` | `FileAccess` |
| `JSON.print` / `parse_json` | `Json.Stringify` / `Json.Parse` |
| `str2var` | 自己做颜色解析 |
| `yield(x, "timeout")` | `await ToSignal(...)` |
| `.instance()` | `.Instantiate<T>()` |
| `class_name Die` | `[GlobalClass] public partial class DieBody : RigidBody3D` |
| `tool` | `[Tool]` |
| `export var` | `[Export]` |
| `onready var x = $Mesh` | `_Ready` 里 `GetNode<MeshInstance3D>("Mesh")` 或 `[Export] NodePath` |
| `connect("sig", obj, "method")` | `SomeSignal += Handler` 或 `Callable` |
| `emit_signal("die_rolled", ...)` | `[Signal] public delegate void DieRolledEventHandler(...)` |
| `setget` | C# 属性 |
| `BUTTON_LEFT` | `MouseButton.Left` |
| `scancode` | `Key` / `Keycode` |
| `Input.CURSOR_DRAG` | `Input.CursorShape.Drag` |
| `shader_param` / `hint_color` | `SetShaderParameter` / `source_color` |
| `PoolStringArray` | `string[]` 或 `Godot.Collections.Array<string>` |
| Autoload 脚本 | 项目设置 Autoload + `public partial class SettingsStore : Node` |

### 4.2 物理与输入

- 刚体模式：`RigidBody.MODE_STATIC` → `RigidBody3D.FreezeMode` / `Freeze` + `FreezeModeStatic`（按 4.7 文档选用等价组合）。锁定角速度用 `AxisLockAngularX/Y/Z`。
- 射线：`cast_to` → `TargetPosition`；`collision_mask` 仍是位掩码，Dice = 层 2。
- `Area.SPACE_OVERRIDE_REPLACE` → `Area3D.SpaceOverride` 枚举。
- 重力点吸取：`GrabArea` 的 `gravity_point` / `linear_damp` 在 Jolt 下要实测；若吸力过弱或过强，只调 Area 参数，不要改判定规则。
- **BoxShape 尺寸陷阱：** Godot 3 `extents=(25,10,25)` 等于 Godot 4 `Size=(50,20,50)`。漏乘 2 会导致场地和生成范围错位。
- 地板碰撞半尺寸用于 `randomize_throw` 时，C# 必须用 **与 Godot 3 相同的半尺寸语义** 计算随机范围，或统一改成全尺寸并改公式。

### 4.3 C# 习惯

- 节点脚本必须是 `partial class`，且类名与文件名一致（Godot 约定）。
- 信号参数用强类型，不要 `Godot.Collections.Dictionary` 传递骰子状态。
- `SettingsData.listen(node, method)` 改为 C# event / 接口 `ISettingsListener`。
- `SettingsWindowDice` 里 `call("apply_" + setting)` 改为 `switch` 或 `Dictionary<string, Action<Color>>`。
- `instance_from_id`：优先在 `DieBody` 上保持托管引用；若必须用 id，用 `GodotObject.InstanceFromId` 并判空。
- 批量添加骰子的 `yield(timer, 0.0003)` 在 C# 用 `await ToSignal(GetTree().CreateTimer(0.0003), SceneTreeTimer.SignalName.Timeout)`，或按帧生成以免一帧刷几十个刚体。

### 4.4 着色器

`outline.shader` / `lock.shader` 从 Godot 3 spatial 迁到 4：

- `shader_type spatial;` 保留。
- `hint_color` → `source_color`。
- `hint_range` 语法核对其是否仍合法。
- 顶点膨胀描边在 Forward Plus 下可能与 GLES2 深度表现不同：无效面边线以“看得见”为准，不必像素级一致。

## 5. 分阶段流程

每阶段：复制或编写 → 编辑器运行 → 勾选检查表 → 再进入下一阶段。不要并行改 UI 和物理直到第 3 阶段通过。

### 阶段 0 — 工程能跑 3D

**做：**

- 删除或停用 `Example` 2D 占位（或留着但不作为主场景）。
- 新建 `scenes/main.tscn`：`Node3D` + `Camera3D` + `DirectionalLight3D` + 一块地板 `StaticBody3D`。
- `project.godot` 设置 `run/main_scene`、窗口 1440×900、stretch `canvas_items` + `expand`、物理层名称 Box / Dice。
- 注册输入动作（项目文档第 9 节），可先只加 `roll` 与鼠标。

**过关：** F5 看到 3D 地板，无 C# 编译错误。

### 阶段 1 — 资源进工程

**做：**

- 从源工程复制 `dice/gltf/`、`dice/materials/`、`dice/d*.tscn`、`Interface/Icons/`、`Interface/Fonts/`、`World/wall.tscn`。
- **不要**复制 `.import`、`.gd`、`addons/`。
- 用 Godot 4 打开，等待导入；修复报错的材质/着色器。
- 骰子 `.tscn`：去掉 GDScript，节点类型改为 `RigidBody3D` 等；暂时可没有脚本，只把一颗 d6 拖进主场景看网格和碰撞。

**过关：** 编辑器里能看见 d6 网格；运行时刚体掉在地板上（即使没有点数逻辑）。

**注意：** 骰子场景很大（内嵌 ArrayMesh）。用 Git 提交二进制前确认 `.gitattributes`。碰撞若在 4.x 中错位，再考虑从 `*collision.gltf` 重建，而不是一上来就重导视觉网格。

### 阶段 2 — 朝上判定（可单测）

**做：**

- `Core/DieFaceMap.cs`：类型、面点字典、`max_side_height_difference`、`GetRolledSide(Transform3D localToWorld)`。
- 把六个 `dN.gd` 的 `sides` **原样**抄成静态数据（含 d4 的负向量）。
- 可选：NUnit / Godot 测试——给单位变换，d6 应得到 6（`Vector3.UP`）。

**过关：** 固定姿态下六种骰子的点数与原版脚本一致；斜放时返回 0。

此阶段不要写 UI。

### 阶段 3 — Die 节点 + Manager

**做：**

- `DieBody`：1 秒轮询发信号、无效描边、锁定、掉落重生。
- `DiceManager`：类型 → PackedScene 字典、`Spawn`、`RandomizeThrow`、`Roll`。
- Autoload：`DiceSession`、`SettingsStore`（可先内存默认值，暂不写 JSON）。
- 无 UI：用 `_UnhandledInput` 按空格生成一颗 d6。

**过关：** 空格出骰，停下后能在远程调试器或临时 Label 看到点数；推下悬崖会再生。

### 阶段 4 — 抓取交互

**做：** 移植 `DiceInteractions.gd`（射线、Y 平面、GrabArea、旋转 Timer、叠放 RayCast）。

**过关（对照 Godot 3 原版）：**

- [ ] 悬停高亮光标
- [ ] 拖拽贴手，朝上面大致朝上
- [ ] 甩出有速度上限
- [ ] 双击 / W 随机抛
- [ ] 右键锁定；锁定外观换材质
- [ ] 拖到另一颗骰子上放下会叠高
- [ ] Backspace 删除
- [ ] 空白处吸取

Jolt 下若骰子更“粘”或更“弹”，只调摩擦/阻尼，不要改面判定阈值（阈值是几何量）。

### 阶段 5 — 场地与相机

**做：** 四面墙、顶、`global_area_scale`、滚轮缩放与改大小、Resize/Zoom Timer。

**过关：** Shift+滚轮改场地时骰子被唤醒；相机距离夹在 4–60。

### 阶段 6 — 统计与设置存储

**做：**

- `DieTypeAggregate` + `DiceSession` 完整移植 `DiceData` / `DieTypeData`。
- `SettingsStore` 读写 `user://settings.json`（自定颜色格式）。
- 重力设置改变时更新所有骰子 `GravityScale`。

**过关：** 多颗混合类型的合计正确；删除后统计消失；改重力立刻生效；重启后颜色还在。

### 阶段 7 — 主 UI

按依赖从少到多：

1. `DiceSelect` + `NumberInput` + 添加/清除/掷/锁按钮  
2. `Statistics` + `DieTypeStatistic`（0.5s 刷新）  
3. 数字键 1–9、原版快捷键  
4. Toast、版本消息  
5. Window / WindowContainer、Settings 三页、Help 快捷键图示  
6. 主题与 IconButton / CheckToggle（可先用 Godot 4 默认主题，再贴原 `*.tres`）

**过关：** 不看 3D 也能靠左侧按钮完成添加与重掷；右侧数字与场上一致；关设置窗口会保存。

指令栏：保留 `use_commands` 开关即可，**不要**在本阶段解析 `4d6d1`。

### 阶段 8 — 复用形态

**做：**

- 最小场景 `test_headless_table.tscn`：只有 Table API，没有 Interface。
- 把 `addons/dice_roller` 拷到一个 **新建的空白 Godot 4 C# 项目**，只写 20 行宿主代码生成骰子并读 `Sum`。
- 补一份短的「嵌入指南」（可加在本文件第 8 节，不必另开文档，除非宿主项目需要）。

**过关：** 空白项目在未复制 `scenes/main.tscn` 的情况下能掷骰读数。

### 阶段 9 — 可选

- 指令语法模块（独立，纯 C#，单测优先）。
- HTML5 / 桌面导出。
- 用自有美术替换 GPL 资源（若宿主不能开源）。

## 6. 单次改动的日常循环

对每一个功能（例如“锁定”）：

1. **在 Godot 3 原版里操作一遍**，记下期望（热键、外观、边界情况）。
2. **只打开相关的原 `.gd` 与 `.tscn`**，列出信号与节点名。
3. **在 C# 写最小实现**，不顺手重构无关 UI。
4. **Play 对照** 项目文档第 6.3 节的交互表。
5. **修 Jolt / Godot 4 差异**（尺寸、冻结模式、着色器），直到规则一致。
6. 若发现原版 bug（例如 General 设置不恢复 `allow_locked_move`，重力默认 4 vs 滑条 fallback 10），在实现注释或本文件「已知原版缺陷」中记录你的选择：复现或修正。

提交（仅在被要求时）：按阶段或按功能提交，不要把“导入 200MB 网格”和“重写交互”混在一个 commit。

## 8. 迁入其他项目

目标结构稳定后（阶段 8）：

1. 复制 `addons/dice_roller/` 到宿主 `addons/`。
2. 宿主 `project.godot`：启用插件或手动 Autoload `SettingsStore`、`DiceSession`（若你把它们放在插件内）。
3. 物理层 1/2 名称与掩码与插件约定一致，或把层号做成导出字段。
4. 实例化插件提供的 `DiceTable.tscn`（场地 + Manager + Interactions），**不要**实例化演示用的完整 Interface，除非宿主也要这套 UI。
5. 代码只依赖 `IDiceTable`（见项目文档 7.1）。
6. 确认宿主许可证能接受 GPL-3.0，或已替换全部源自 Hundred Dice 的资源与派生代码。

输入动作名称建议保持与原版相同（`roll`、`lock_dice` 等），宿主可在自己的 Input Map 里改键位，不必改插件代码。

## 10. 已知原版缺陷（移植时必须做选择）

| 现象 | 位置 | 建议 |
|------|------|------|
| `DebugDraw`、`dice_syntax` 缺失 | `project.godot` | C# 版不注册 |
| 指令输入无解析 | `CommandInput.gd` | 一期只做 UI 壳或隐藏 |
| `camera.gd` 未挂载 | `World/camera.gd` | 不移植 |
| `allow_locked_move` 不在 `apply_settings` 的 match 里 | `SettingsWindowGeneral.gd` | C# 版应读写并恢复该开关 |
| 重力 fallback：Manager 4 vs 滑条 10 | `DiceManager.gd` / General | 统一默认 **4**（与骰子场景 `gravity_scale` 一致） |
| `roll()` 不解锁 STATIC 骰子 | `DiceManager.roll` | 建议重掷前恢复刚体，属于体验修正 |
| HTML5 光标 Drag/CanDrop 对调 | `DiceInteractions.gd` | 用 `OS.HasFeature("web")` 保留 |
| `Help.gd` 等出现在导出列表但不在源树 | `export_presets.cfg` | 忽略 |

把选择写在对应 C# 文件的简短注释里，避免以后“修回原版 bug”。

## 11. 风险

| 风险 | 缓解 |
|------|------|
| Jolt ≠ Bullet，落地更抖或更稳 | 只调物理材质与 `physics_ticks_per_second`；阈值不跟手感乱改 |
| Godot 4 导入打爆 Convex 碰撞 | 用 collision gltf 或简化凸包；d6 继续用盒子 |
| 内嵌网格导致仓库膨胀 | 接受，或改为运行时加载外部 gltf（工作量大，一期不建议） |
| `[Tool]` 控件在编辑器里跑 `_Process` | IconButton / CheckToggle / Shortcut 移植时限制 `Engine.IsEditorHint()` |
| 语言服务找不到 Godot 类型 | 不要删 `Directory.Build.props` |
| 闭源宿主误用 GPL 资源 | 阶段 8 前做一次资源来源审查 |
